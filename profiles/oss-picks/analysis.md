# Evaluation goal

Evaluate whether a developer would find this open-source project genuinely useful or fun to try today.

# Scoring rubric

- **9-10: Standout.** Immediately useful to many developers or genuinely novel, with clear docs and active development.
- **7-8: Recommended.** Useful or interesting with a concrete use case, reasonable docs, and recent activity.
- **5-6: Niche.** Solid but narrow, or promising but early.
- **3-4: Low value.** Thin wrapper, unclear purpose, stale, or low quality.
- **0-2: Noise.** Spam, abandoned, non-open-source, or off-topic.

# Evaluation guidance

Prefer projects with a public repository, a clear README, a license, and recent commits. Give a strong bonus to young projects (created within 90 days) with rapid star growth, a clear README, and a concrete use case. Penalize mature projects that are merely popular or long-established unless the item is a major new release. Novelty matters, but so does practicality. Penalize hype without code. Use three to five topic tags.
